# Codex CLI на финской VM

## Оценка для FI-RZ-1

1 vCPU / 2 GB RAM / 32 GB NVMe должны подходить для одной сессии CLI, чтения
небольшого репозитория, Git и SSH, если VPN оставляет достаточно ресурсов.
Это предварительная инженерная оценка, не измерение данной VM.
При обычном OpenAI provider модель выполняется удалённо; на VM работают клиент
и запускаемые им инструменты. Не выбирать локальный Ollama/LM Studio provider.
Веса, Torch, восстановление моделей и эксперименты остаются на GPU-сервере.

Для планирования оставляем 0.5–1 GiB свободной RAM для клиента и лёгких команд.
Это запас, а не официальный минимум и не прогноз постоянного потребления.
При менее 0.5 GiB MemAvailable сначала разбираемся с реальной нагрузкой.
Один CPU достаточен для управления SSH, но интенсивный VPN-трафик и большие
поиски могут конкурировать за него. Запускаем одну сессию CLI; тяжёлые процессы
на VM не запускаем. `nice -n 10 codex` снижает её CPU-приоритет.

## Что измерено в облаке, не на VM

9 октября 2026 скачан официальный Linux x86_64 musl release `rust-v0.162.0`:
архив 111,393,227 байт, бинарный файл 294,410,952 байта (около 281 MiB).
SHA256 архива проверен по digest официального GitHub release:
`8daf67f6261161aa5939d8d42a516032d760406216779d7ce6040f242140ff73`.

Отдельный `codex app-server --stdio` получил только `initialize`, без создания
чата, обращения к модели или выполнения команд. За 10 секунд процесс:
пиковый RSS около 99.3 MiB, CPU time около 0.12 секунды. Это расход простаивающего
управляющего процесса, не всей активной CLI-сессии. Длинный контекст, инструменты,
интерфейс и плагины могут расходовать больше. Официальный installer может также
скачать дополнительные файлы. Под установку, историю и код разумно оставить
1–2 GB диска; это бюджет, не размер одного бинарного файла.

## Измерить VM без изменений

В существующем SSH-терминале VM, при обычном использовании VPN:

```sh
free -h
df -h /
vmstat 1 10
docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'
ps -eo comm,pcpu,rss --sort=-rss | head -15
```

Первая строка vmstat показывает среднее с загрузки; смотрим следующие строки.
`id` — доля простоя CPU, `si/so` — активность swap, `st` — время, отнятое
гипервизором. Docker stats показывает контейнеры; VPN может обрабатывать часть
трафика в ядре, поэтому смотреть только CPU контейнера недостаточно. Общая
нагрузка vmstat включает системную обработку трафика. RSS в ps указан в KiB.
Команды не выводят полные аргументы процессов, переменные окружения или пароли.
Разовый снимок не доказывает отсутствие пиков: проверять при характерном трафике.

## Простая установка

Запускаем клиент от обычного пользователя VM. Если есть только root, из его
терминала можно сначала создать отдельную учётную запись (если её ещё нет):

```sh
adduser --disabled-password --gecos "" research
su - research
```

Далее от этого пользователя:

```sh
curl -fsSL https://chatgpt.com/codex/install.sh -o /tmp/codex-install.sh
sh /tmp/codex-install.sh
~/.local/bin/codex --version
~/.local/bin/codex login --device-auth
git clone --branch research/prepare-checkpoint-study https://github.com/kkoottiiaarraa/lora-dora-research.git ~/lora-dora-research
cd ~/lora-dora-research
nice -n 10 ~/.local/bin/codex
```

Это официальный standalone installer; Node.js/npm и сборка Rust не требуются.
При device login открыть показанную ссылку в своём браузере и ввести одноразовый
код. Возможно, нужно включить device code login в ChatGPT Security settings.
Использование через ChatGPT учитывается в доступных лимитах плана; API key login
использует отдельный API billing. Файлы авторизации не переносить в Git или чат.
Если git/curl отсутствуют, ставить их только на собственной VM перед этим шагом.

Текущий облачный чат автоматически в CLI не переносится. Начальное задание:

> Прочитай AGENTS.md, LORA_DORA_RESEARCH_CONTEXT.md, CHECKPOINT_INVENTORY_2026-10-09.md,
> docs/RESEARCH_PROTOCOL.md и docs/HANDOFF.md. Ты работаешь на финской VM, здесь
> только код и управление. Подключайся обычным SSH к kotelnikovni@185.185.59.19.
> На GPU-сервере создай новый checkout рядом с существующим, существующий не трогай.
> Сначала выполни только диагностику сервера. Далее подготовь ранее согласованный
> пилот Qwen3-4B/GSM8K на одной свободной GPU; общий предел — три GPU.
> Все веса, зависимости Torch и тяжёлые запуски размести на GPU-сервере.

SSH host key при первом входе проверяется обычным способом. SSH-аутентификация
GPU-сервера ещё не проверена. VM-клиент должен получить доступ к обычному SSH
через выбранные локальные разрешения Codex; cloud TCP grants к нему не относятся.
Sudo на GPU-сервере не нужно. Для долгой работы удобно держать CLI в tmux, если
он установлен. Не создавать HTTP API, Cloudflare tunnel или новую VPN.
