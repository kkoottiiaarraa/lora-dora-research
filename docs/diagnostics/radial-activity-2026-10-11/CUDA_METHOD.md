# CUDA normalizer diagnostic

Cached BF16 base and saved FP32 A/B/m, scaling1, 144 GSM8K attention modules. No model construction, activation forward, generation or training. One GPU, two CPU numerical threads; allocator capped2GiB. Owned tensor release is checked via weak references; residual backend workspace allocator bytes are recorded before exit. Pilot/full PID absence in nvidia-smi verifies exit afterward. Two initial cleanup-validation attempts are retained in server-only failure directories; these did not alter norm arithmetic.

Under CUDA BF16 autocast, build full FP32 identity, apply two F.linear operations, transpose BF16 product, add to FP32 base, compute FP32 row norm and FP32 quotient. Every module norm is bitwise compared with installed PEFT DoraLinearLayer.get_weight_norm. Flags are recorded without modification. A direct B@A shortcut is not used.

CUDA rows join accepted CPU idealFP32 and full two-linear CPU BF16 surrogate by exact module/row/m on server CPU after CUDA exits. Same CUDA BF16 product is separately reduced on CPU, separating norm reduction from product differences. All quantiles pool actual rows; global Frobenius ratios use sums of FP64 squares of FP32 radial/total differences. Fixed-base-norm endpoint residual and reset perturbation are separate from unknown training initialization. Relative quotient errors exclude and explicitly count reference-zero rows, yielding null if all references zero. BF16(g)==1 is a counterfactual cast: actual quotient is FP32.

Pilot/full reproducibility tolerance was fixed at8FP32 eps relative and0 absolute, before seeing results. Exact comparisons and measured errors are retained. CUDA tensor wall and stream-event intervals include host synchronization gaps between operations; neither measures pure compute or utilization. Process-minus-initial-hashio is an approximate residency upper bound through metadata snapshot, excluding import startup and tiny final writes. Failed cleanup attempts retain raw artifacts and separately reported measured tensor intervals, with full failed process times unavailable. No p-values over rows/modules. Normalizer agreement does not establish full-function equality or a training cause.

Raw paths, hashes, library/source/input/spec/output provenance are in cuda-manifest.json. Raw rows/logs remain server-only.

NVIDIA process VRAM is the maximum sampled at module boundaries, not a continuous peak. PyTorch allocated/reserved peaks are allocator tracked peaks. CUDA Rm uses the CUDA FP32 base row norm; descriptive joined endpoint m/base residuals use the accepted CPU FP32 base row norm. These are separately specified arithmetic references. The final pilot and full run use the identical frozen code SHA recorded in validation; an earlier accepted pilot used the same numeric path before deferred-join reporting edits, and its artifact directory is archived. Earlier exact source bytes were not separately saved, so only recorded code hashes are preserved.
