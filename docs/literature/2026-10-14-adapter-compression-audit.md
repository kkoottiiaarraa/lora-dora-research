# Сжатие готовых DoRA: предшественники и границы следующего шага

Поиск начат 13 октября, завершён 14 октября 2026. Использован обычный веб-поиск
с чтением первоисточников и авторских репозиториев. Scite, Deep Research, агенты,
модельные прогоны и скачивание весов не использовались. Это целевой обзор,
не исчерпывающий систематический обзор и не доказательство отсутствия предшественника.

## Решение для проекта

**Готового нового алгоритма у нас пока нет.** Самостоятельными новыми вкладами
нельзя считать SVD готового адаптера, QR-ускорение этой операции, распределение
рангов по сингулярным значениям, whitening, пересчёт коэффициентов по локальной
регрессии или совместное сжатие Q/K и V/O. Для этих принципов найдены близкие
предшественники; различия постановок перечислены ниже.

Рабочая ниша для проверки: **сжатие готового weight-decomposed DoRA-адаптера
при неизменной общей базе и точном бюджете сохраняемых параметров**, с измерением
качества ответов. Наличие этой комбинации ограничений ещё не является вкладом.
Нужны существенная ошибка сильного сравнительного метода, её объяснение и
исправление, полезное на новых данных. В прочитанных работах не установлено
точное совпадение всей этой постановки с готовым решением. Это ограниченный
результат поиска, а не заявка на первенство.

## Постановка и то, что уже проверено

Для матрицы формы `[out, in]` используем обозначения проекта:

\[
W_* = D_*(W_0+BA),\quad
\Delta_*=(D_*-I)W_0+D_*BA.
\]

`W0` — неизменная база; масштаб LoRA включён в `BA`. `D*` — диагональ
эффективных множителей, а не вектор магнитуд `m`: множитель включает нормировку.
Полное `Delta*` не обязано быть низкоранговым. Направляющая часть `D*BA`
низкорангова. Это следствие формулы, не объяснение обучения или качества DoRA.

Сравнивались классы `W0+LR` и `DW0+LR`. Для матрицы `m×n` их бюджеты
элементов равны соответственно `r(m+n)` и `m+r(m+n)`. При разных dtype
сравнивать нужно байты; для файлов отдельно считать заголовки и метаданные.
Сохранение `D` не означает сохранение исходного `m`: при изменении направления
знаменатель нормы тоже меняется. При экспорте в native DoRA это нужно учитывать.

Исходная DoRA занимает 23,906,304 элемента FP32. В последних проверках все
144 q/k/v/o проекции сжимались до равных бюджетов внутри каждого сравнения:
11,796,480 и 5,898,240 элементов. Это уменьшение **адаптера**, не всей модели.
Из [полного screen](../analysis/2026-10-13-full-compression/REPORT.md): сохранение
исходного D улучшило teacher KL против W-SVD на 27.09% при половинном бюджете,
но ухудшило на 10.50% при четверти. Из [новой validation](../analysis/2026-10-13-radial-recalibration/REPORT.md):
пересчёт D улучшил fixed-D вариант лишь на 0.8089%, оставшись хуже W-SVD на
7.0818%. Кандидат отклонён. Эти числа относятся к gold-prefix KL, не к доле
правильно решённых задач; два этапа использовали разные наборы вопросов.

## Сравнение ближайших работ

Формулы в таблице записаны в единых обозначениях для сравнения, если явно не
указано иное. `S S^T = C` — статистика входных активаций, `T_r` — усечённый SVD.
«Без обучения» здесь означает отсутствие градиентного дообучения весов модели;
сбор активаций, обратных сигналов и аналитическая подгонка отдельно оговариваются.
Наличие авторского кода не означает, что мы воспроизвели его результаты.

## Два уточнения, которые предотвращают ложные выводы

1. **Две разных DoRA.** PARA цитирует Mao et al.,
   [Dynamic Rank Distribution](https://arxiv.org/abs/2405.17357), а наш проект
   исследует Liu et al., [Weight-Decomposed LoRA](https://arxiv.org/abs/2402.09353).
   Сравнения PARA с названием DoRA не доказывают, что там проверено сжатие нашей DoRA.
2. **Три разных обозначения SVD-LLM.** arXiv 2403.07378v2 и v5 — версии одной
   работы с разными recovery stages. SVD-LLM V2, arXiv 2503.12340 — отдельная
   работа. Ранее мы ссылались на закрытую форму из старого v2; при описании
   современной полной процедуры это необходимо оговаривать. Наши результаты
   от этого не меняются: полная процедура не была реализована ни в одной версии.

## Что не стоит реализовывать как якобы новый метод

| Предложение | Решение аудита |
|---|---|
| SVD/QR-SVD готового BA; energy threshold; единый бюджет рангов | Уже есть прямые предшественники. Использовать как baseline. |
| Activation whitening полного обновления | Известный objective; наша адаптация не новый общий принцип. |
| Ещё одна сетка нормировок/масштабов | Пересечение с learned scaling, плюс предыдущие отрицательные результаты. Не расширять без новой конкретной причины ошибки. |
| Ещё один D-only шаг при неизменном LR и том же objective | Наш закрытый шаг уже решает эту локальную задачу. Новая итерация не исправляет ограничение класса. |
| Просто совместно сжать V/O либо Q/K | Предшественник есть; даже его простая VO версия имеет опубликованное ограничение. |
| Добавить компенсационный LR поверх сжатия и не учесть память | Нечестный бюджет. При равном бюджете это известная residual-correction стратегия, а не бесплатный выигрыш. |
| Заявить, что спектральные признаки бесполезны | Наши изменения геометрии этого не доказывают. Нужно показать неверное полезное решение при фиксированных ресурсах и сравнении с сильным правилом. |

Смежный источник для последнего пункта:
[Spectral Statistics Predict LLM Compression Degradation, v1](https://arxiv.org/html/2604.18085v1).
Он изучает предсказание деградации по спектральным статистикам полных моделей,
а не механизм обучения DoRA. Наша неинвариантность не опровергает его корреляции
на выбранном авторами представлении. Для критики нужен тест области применимости.

Оценка приоритетов — наша интерпретация обзора. Отсутствие точного совпадения
в найденной литературе не делает каждый вопрос новым. Ни одному направлению
здесь не присваивается обещание B/A.

## Минимальное ТЗ перед следующей реализацией

Сначала выбрать **одну** причину ошибки и **один** ближайший сравнительный метод,
а не запускать все строки таблицы. Необходимые результаты следующего решения:

1. Сформулировать разницу objective и допустимых параметров с конкретным
   предшественником. Записать, почему его решение не отвечает нашим ограничениям.
2. Проверить на уже сохранённых данных, есть ли ожидаемая ошибка. Анализ
   факторов без нового инференса может проверить бюджеты/локальные хвосты,
   но не может установить качество генерации или глобальную причину потерь.
3. Если нужна новая реализация baseline, зафиксировать версию, математические
   изменения для fixed W0, обработку D и точный размер. Отдельно учитывать
   калибровочные данные, обратные проходы и оптимизацию. Не называть перенос
   полным воспроизведением авторского алгоритма.
4. Для нового кандидата заранее выбрать новую validation, primary metric,
   бюджет и практический порог. Проверять teacher fidelity и ответы на задаче
   раздельно. Старые validation нельзя использовать для нового подбора.
5. Расширять на другую модель после содержательного преимущества. Экономия
   адаптера не равна ускорению всей модели; latency измерять, если это часть заявки.

**Рекомендация:** первым выбирать между ошибкой allocation и ошибкой локальной
аппроксимации. Для allocation ближайшие ориентиры PARA/SVD-LLM V2/LEMS; для
аппроксимации — W-SVD/AIR/KFAC и структурный fixed-D вариант. Пока не установлено,
какая причина доминирует. Очередная широкая сетка вмешательств не обоснована.

## Воспроизводимость поиска и ограничения

Искались сочетания `DoRA adapter post training compression radial direction`,
`LoRA post-training compression rank allocation activation`, точные названия
найденных работ и авторский код. Цепочка чтения: LoRA-Squeeze → связанные
posthoc методы; SVD-LLM → версии/V2; activation/influence compression → AIR,
EoRA, SigmaScale, LEMS; DoRA factor compression → ChainDoRA. Просмотрены
методические разделы указанных статей, авторские README для AIR, EoRA,
SigmaScale, SVD-LLM и LEMS. Для LEMS проверены proceedings abstract, проектная
страница и README; полный математический/реализационный аудит не выполнен.

Основные новые для этого аудита ориентиры — PARA, LEMS/KFAC-SVD и ChainDoRA.
Проверены адреса и описания кода, но ничего не установлено и не запущено.
URL без подтверждённого официального кода отмечены явно; «не найден» не равно
«не существует». Авторские результаты не пересчитаны. Модельные веса,
неизвестные training seeds и возможные расхождения их протоколов не проверялись.
Сводная таблица для дальнейшей работы: [comparison.csv](2026-10-14-adapter-compression-comparison.csv).

Операционные данные сервера в этом обзоре отсутствуют. Предыдущие результаты
сохранены без изменений. Ни commit, ни push в рамках этого этапа не выполнялись.
