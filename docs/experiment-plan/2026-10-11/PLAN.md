# Следующие эксперименты: специфичность и границы роли радиальной части DoRA

Дата: 11 октября 2026. Статус: предложение, новые модельные прогоны не запущены.
Последнее решение пользователя: все запросы HF отклонены; закрытые базы не использовать.
Answer.AI исключён из следующего блока. Qwen3-8B и LLaVA остаются исключёнными.
Новые модели не обучаем. Статью сейчас не пишем.

## 1. Какой результат пытаемся получить

Вопрос: **когда дополнительная радиальная часть DoRA нужна при применении готовой
модели, и специфична ли наблюдаемая устойчивость к её удалению?**

Наше наблюдение на Qwen3-4B/GSM8K: радиальный компонент действительно активен,
но его удаление не ухудшило среднюю точность в имеющемся опыте. Это ещё не
объяснение преимущества DoRA: сама модель может быть устойчива к разным
возмущениям подобной силы; другие задачи могут обнаружить потерю способности.
Доказательства причины обучающей траектории из конечных весов получить нельзя.

Кандидат на самостоятельный вклад: различить эти объяснения контролями,
установить границы на другой задаче и другом семействе, проверить скрытый
компромисс между целевой задачей и качеством вне её. Нужен результат, который
меняет вывод при любом исходе, а не очередная таблица корреляций.

Уже известно из литературы: замораживание magnitude при обучении
([DeLoRA](https://arxiv.org/html/2503.18225v1)), спектральная структура DoRA
([SORA](https://ojs.aaai.org/index.php/AAAI/article/view/40267)), постфактум
ослабление компонентов с контролем и оценкой других способностей
([Intruder dimensions](https://arxiv.org/html/2410.21228v3)).
Просто «удалили компонент, качество сохранилось» и «сжали адаптер» сами по себе
не являются достаточной новизной. Даже положительный результат следующих
опытов не гарантирует публикацию.

## 2. Проверка доступных пар

Первый кандидат — авторская пара Spectral Adapter:

- база [mistralai/Mistral-7B-v0.1](https://huggingface.co/mistralai/Mistral-7B-v0.1);
- [LoRA-r16](https://huggingface.co/fzzhang/mistralv1_lora_r16_25e5_e03);
- [DoRA-r16](https://huggingface.co/fzzhang/mistralv1_dora_r16_25e5_e03);
- [авторский код](https://github.com/pilancilab/spectral_adapter/tree/main/mistral_tune).

База и адаптеры публичны, API сообщает gated=false. Карточки совпадают по
LR=2.5e-5, 3 эпохам, seed=0, batch и версиям. Архивный аудит подтвердил
rank16/alpha32/dropout0.05, одинаковые target modules, настоящие magnitude у
DoRA. Код использует GSM8K train; README оценки описывает 5-shot strict match.
**Пробел:** карточки конкретных весов пишут dataset=None, базовый revision не
зафиксирован. Совпадение автора/суффиксов не доказывает идентичность обучения.
До полного запуска восстановить связь checkpoint → preprocessing/данные/режим
оценки. Если она не восстанавливается, разрешено лишь явно ограниченное
исследование вмешательства внутри этих весов, а не чистое сравнение методов.
Не подменять исходную базу чужим зеркалом или другой квантованной версией.

Небольшой резерв — [AraT5 LoRA](https://huggingface.co/yasmineee/araT5-Base-with-LoRA)
и [DoRA](https://huggingface.co/yasmineee/araT5-Base-with-DoRA) на
UBC-NLP/AraT5v2-base-1024: r5/alpha32/dropout0.06 совпадают, но точный датасет и
split неизвестны. Название других OPUS100-релизов автора не решает этот пробел.
Не запускать автоматически ради разнообразия архитектур.

Другой найденный источник: snunlp/bigdata_exaone3_7.8b_{lora,dora} и
snunlp/bigdata_qwen2_7b_{lora,dora}. Список API показывает имена, но README и
adapter_config обеих пар при текущей анонимной проверке вернули HTTP401.
Не считать их доступными готовыми парами и не тратить время на обход доступа.
PeRL имеет несовпадающие LR/ранги и дорогое длинное декодирование; пока отложить.

Машиночитаемые снимки metadata и короткие проверки доступа к весам:
`open-candidates-audit.json`. Это проверка доступности, не успешная загрузка.
Поиск ограничен; отсутствие других чистых пар не доказано.

## 3. Эксперимент A — специфично ли удаление D?

Приоритет 1. Используем готовый Qwen3-4B/GSM8K и существующие original/removeD
результаты, если вычислительный путь точно совпадает. Добавляем два контроля:

1. Переставляем радиальные коэффициенты между строками каждой матрицы:
   проверяем важность их расположения.
2. Ослабляем часть обученного низкорангового обновления сопоставимой силы:
   сравниваем с изменением другого обученного компонента, не только с шумом.

Идеальные формулы: U=W0+L, g=m/||U||row, WD=diag(g)U, R=diag(g−1)U.
Удаление D: WD−R; перестановочный контроль: WD−c·diag(P(g−1))U;
направляющий контроль: WD−c·L. Формулы не отменяют проверки реального PEFT/BF16
пути: промежуточное округление может менять функцию.

Силу контролей подбираем по энергии изменения выходов адаптированных модулей
на **одинаковых входных активациях исходной модели**, около 200 обучающих
примеров, с проверкой на отдельной калибровочной части. Настройка по test
accuracy запрещена. Нормы весов также сохраняем, но не обещаем одновременно
совпадающие нормы весов и активаций при одном масштабе. Если сопоставление
плохо переносится на отдельную калибровку, исправляем контроль до полной оценки.

Оценка: полный GSM8K test, final exact match — основная метрика; старый scorer —
проверка чувствительности. Два заранее заданных парных контраста: removeD
против каждого контроля, доверительные интервалы и Holm для этой семьи.
Фиксируем seed перестановки до просмотра результатов; одна перестановка не
доказывает типичное поведение случайных контролей. Сильный вывод требует
дополнительного заранее фиксированного seed, отдельного бюджета и отчётности.
Нынешний GSM8K test уже использовался для выбора гипотезы: это исследовательский,
а не независимый подтверждающий опыт.

Решение:

- removeD сохраняет качество, оба контроля надёжно хуже: аргумент в пользу
  специфичности D на этой паре; затем проверка на другом checkpoint;
- сопоставимые контроли также сохраняют качество и интервалы достаточно узки:
  объяснение общей устойчивостью, сильную D-специфичную гипотезу снимаем;
- интервалы широкие: неопределённость, а не эквивалентность. Не расширять
  автоматически сетку локализаций ради получения значимости.

Случайный контроль, который оказался хуже, сам по себе слабый результат:
случайное изменение часто вреднее структурированного. Поэтому нужен второй
контроль и перенос на другую пару. На 1319 вопросах строгую сохранность в 0.5
п.п. можем не разрешить статистически; не обещать её заранее.

## 4. Эксперимент B — перенос на задачи без явного выигрыша DoRA

Приоритет 2. Два новых removeD прогона готовых Qwen3-4B/MMLU и SQuADv2.
Их base/LoRA/DoRA результаты уже есть — не повторяем без технической причины.
Для SQuAD заранее сохраняем exact/F1 и разделение answerable/unanswerable:
общая средняя может скрыть ухудшение отказа от ответа.

Если A даёт различающий результат, повторяем оба его контроля на MMLU как
заранее выбранной дешёвой второй паре. Это другие task-specific адаптеры,
но та же архитектура, не независимые training seeds и не другое семейство.
Метрики и допустимую потерю фиксировать отдельно для каждой задачи до запуска;
не смешивать F1 и точность и не объявлять отсутствие значимости сохранностью.

## 5. Эксперимент C — не скрывает ли целевая оценка другую потерю?

Приоритет 2, небольшой дополнительный блок. На фиксированном общем тексте
(WikiText-2 test, revision и 1024 сегмента по 256 токенов фиксируются заранее)
измерить next-token NLL для base, LoRA, DoRA и removeD математической пары.

Если GSM8K сохраняется, а NLL ухудшается, D выполняет роль, которую целевая
средняя не обнаруживает. Если изменений нет с достаточной точностью, граница
устойчивости шире. Это качество на тексте вне целевой задачи, **не доказанное
забывание предобучения**: исходный pretraining corpus неизвестен. NLL нельзя
выдавать за полную оценку reasoning или instruction following.

## 6. Эксперимент D — другое семейство, только одна открытая пара

Приоритет 3, после аудита Mistral и пилота стоимости. Выбранная выше r16/e03
пара задаётся до получения нашей оценки, без перебора «где DoRA победила».
Минимум три условия: LoRA, DoRA, DoRA без D. Затем максимум один наиболее
информативный контроль из A, если он нужен для проверки конкретного вывода.
Полный base прогон не нужен для контраста DoRA/removeD; короткий base нужен
для проверки загрузчика. Сохраняем авторскую оценку и точно документированный
общий способ извлечения ответа. Различия с Qwen prompt/shot не приписывать
только архитектуре.

Если DoRA выигрывает и удаление D сохраняет выигрыш — отделяем необходимость
финального компонента от полезности параметризации; причину обучения всё ещё
не устанавливаем. Если удаление вредит здесь, но не на Qwen — обнаруживаем
границу, а не универсальную ненужность D. Если DoRA не выигрывает — это тоже
содержательный случай, не повод искать следующую победившую пару.
Несовпадение с опубликованной оценкой сначала требует проверки протокола,
а не заявления об опровержении статьи.

## 8. Когда материала становится достаточно, а когда останавливаемся

Более сильный материал: контролируемое различие между D и сопоставимым
обученным компонентом, повторяемое хотя бы на другой паре, плюс ясная граница
на другой способности или другом семействе. Возможен и сильный отрицательный
результат, если он с достаточной точностью отвергает содержательную гипотезу.
Только повторение сохранности средней на трёх Qwen задачах — ограниченная
репликация; только один вредный случайный контроль — недостаточный механизм.

Если A не различает объяснения и B/C не дают содержательной границы,
останавливаем расширение сетки и пересматриваем исследовательский вопрос.
Если открытая независимая пара не проходит аудит, честно ограничиваем область
вывода. Объяснение причин преимущества при обучении потребовало бы отдельного
будущего плана с контролируемым обучением; нынешний запрет не обходим.
