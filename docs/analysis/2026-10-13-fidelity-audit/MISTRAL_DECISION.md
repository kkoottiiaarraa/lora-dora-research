# Решение: короткая репликация геометрического тезиса

13 октября 2026. **Рекомендована подготовка одной короткой репликации внутри
готовой Mistral DoRA. Очередь не создана, новые вычисления не запущены.**
Основание: Qwen показал большой локальный сдвиг авторской entropy statistic
при проверенном сохранении функции в FP32. Проверять то же наблюдение на другом
семействе оправданно; полная новая quality-серия пока не отвечает этому вопросу.
Этот документ заменяет предложение полного Mistral GSM8K блока от12октября
для текущего следующего этапа. Старый план остаётся историческим.

## Минимальный состав

Один уже скачанный fzzhang/mistralv1_dora_r16_25e5_e03, без поиска лучшей пары.
База mistralai/Mistral-7B-v0.1@27d67f1b5f57dc0953326b2601d68371d40ea8da;
DoRA@c4e99622a6e01dda3ef3b1cb4e20cbf938a71c7b.

Первым нужен **CPU FP32 reference**, допускаемый на вычислительном сервере:
для главного геометрического тезиса GPU вообще не обязательна. Проверить запас
RAM и загрузку CPU перед загрузкой модели, до4потоков, без новых зависимостей.
Веса остаются на сервере. Не выдавать FP32 promotion сохранённых весов за
исходный несохранённый FP32 training checkpoint.

1. Проверить base/adapter revisions, точное совпадение tensor values, bias-free
   V/O, GQA и полный список адаптированных модулей. У этой пары есть gate_proj:
   полный removeD обязан включать его, V/O gauge gate не меняет.
2. Заранее выбрать слои0/15/31 для 32-layer конфигурации; при иной конфигурации
   остановиться и исправить спецификацию до измерений. Шесть матриц V/O,
   c=.995/1/1.005, 18SVD, та же entropy p=sigma²/sum(sigma²).
3. Те же правила64train cases×32gold-prefix positions, исключить прежнюю
   calibration/test и фиксированные few-shot демонстрации. Зафиксировать5-shot
   plain-text template и демонстрации до forward, не переносить Qwen chat template.
   Входы не обрезать молча: проверить их длины и допустимый context.
4. Full64: original, оба gauges, full-removeD. Только4: repeat_original,
   оба gauged-removeD. Full-vocabulary logits metrics и source/input hashes.
   Unit/block FP64 сначала. Все параметры точно восстанавливаются.
5. Допуск спектров: оба средних gauge RMS≤1% среднего removeD RMS, как у Qwen;
   дополнительно публиковать absolute errors/KL/argmax. Не выбирать c по исходу.

На этом этапе не нужны LoRA/base quality, directional control, generation test,
WikiText, новые локализации или grid. BF16/official merge вторичны: они отвечают
численному сюжету, уже известному в литературе. Добавлять их только под отдельный
сформулированный вопрос; для precision-only причинности нужен общий backend.
Не пытаться разместить FP32 7B на одной16GiB GPU и не подменять reference autocast.

## Расход и остановка

Точный ETA пока не измерен. Защитный CPU timeout4часа, не целевой расход;
после первых4cases пересчитать прогноз и прекратить расширение при превышении.
Главная репликация требует **0GPU-ч**, если выполнена на CPU, как предложено.
GPU1 по-прежнему исключена при любом последующем GPU-пилоте.

- Если fidelity gate не пройден, не интерпретировать спектры как изменения
  сохранённой функции; сохранить ошибку и проверить реализацию.
- Если обе функции сохраняются и exp(H) локально меняется заметно, зафиксировать
  независимый checkpoint witness. Порог «≥1.2 раза хотя бы в одной выбранной
  матрице» — заранее выбранный screen практической величины для этой репликации,
  не p-value, не критерий публикационной новизны и не универсальная граница.
  Публиковать все6матриц и оба c, включая отрицательные результаты.
- Если локальный эффект слаб, не подбирать c или другую пару ради успеха.
  Точный контрпример остаётся верным, эмпирическая общность ограничивается.
- Независимая репликация не заменяет проверку приоритета точного утверждения.

Неизвестное происхождение r16/e03 относительно доступного авторского r8/e02
script сохраняется. Оно не запрещает алгебраический аудит внутри одних весов,
но запрещает чистую атрибуцию различий между методами или обучением.
