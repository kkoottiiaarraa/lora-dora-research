# Малая проверка SORA завершена: целиком опровергать статью оснований нет

14 октября 2026. Пользователь просит ограничить эту ветку и вернуться
к основным неалгоритмическим направлениям. Stdlib CPU, без моделей, обучения,
агентов, GPU и писем авторам. [Числа и code call sites](claim-screen.json),
скрипт `execution/scientific-analysis/sora_claim_screen.py`.

## Что подтвердилось, а что ограничено

1. **Theorem1 о заданных спектрах верна при своих предпосылках.** Независимо
   получена положительная формула entropy difference, включая общий denominator
   E; три допустимых примера совпали до1e−12. Ошибочная промежуточная запись
   или лишнее beta>gamma в доказательстве не делают итог ложным: достаточно
   alpha>beta и alpha>gamma, которые следуют из условий.
2. **Больший ранг сам по себе не обеспечивает большей entropy.** При W0=I4,
   directional rank2 и равной энергии delta=2 имеем H_LoRA=.693147,
   H_DoRA=.001636; DoRA delta имеет rank4 и положительный m.
   Это ограничивает обобщение на любые checkpoints, **не опровергает Theorem1**:
   контрпример не удовлетворяет её специальным спектральным предпосылкам.
3. **Weyl upper bound не доказывает ненулевые singular values.** Неизменная база
   I3, rank1 L=diag(−.5,0,0), D=diag(2,1,1) дают D(W0+L)−W0=0.
   Ненулевые D и L могут взаимно компенсироваться. Возможность high-rank DoRA
   при этом остаётся верной; универсальная необходимость не следует из capacity.
4. **Theorem2 содержит несогласованную нотацию P/T1.** Буквально при generator0
   и P=I получается ||exp(P)−T1(P)||=e−1>.01. Это не содержательное опровержение
   идеи малых вращений: корректная first-order формула для skew K имеет
   remainder<=||K||²/2, defect<=||K||². Product-normalization статьи даёт
   ||K||<=epsilon. Code sum-normalization эту гарантию не наследует, как уже
   показал предыдущий audit. Фактический defect trained checkpoints неизвестен.

Источник формулировок: [SORA arXiv v2, Theorems1–2](https://arxiv.org/html/2511.00051v2).
Наши counterexamples и algebra не являются измерениями task accuracy.

## Может ли исправление loader изменить научный вывод?

**Может, но знак и величина неизвестны.** Исправленный loader восстанавливает
заявленный метод вместо LoRA-only вычисления. В фиксированном2-class примере
он меняет predicted class: для одного gold label accuracy улучшается, для
другого ухудшается, для равной смеси не меняется. Расхождение logits19.6%
из прошлого tiny test не является прогнозом изменения реальной accuracy.

Call-site audit pinned official commit уточняет scope:

- `run_glue.py`: custom SORA mapping зарегистрирован до get_peft_model;
  оценка идёт через trainer.evaluate текущей модели. В этом видимом пути нет
  повторного построения plain LoRA loader. Нет основания автоматически
  приписать reload bug всей GLUE таблице. Условия скрытых execution runs неизвестны.
- `evaluate_gemma_math.py`: PeftModel.from_pretrained без SORA mapping.
  Этот опубликованный путь оценки подвержен найденной потере компонентов.
- опубликованный lm-evaluation-harness восстанавливает mapping для polar/rplora,
  не SORA; merge_and_unload в проверенных evaluation call sites не найден.

Следовательно, исправление loader — **потенциально существенная проверка
конкретных inference paths**, но не общее опровержение superiority или entropy
объяснения. Для проверки конкретных авторских чисел нужны артефакты либо
отдельная training replication; первое отложено пользователем, второе запрещено.

## Решение

Ограниченный этап закрыт. Нет математического результата, который сейчас
позволяет объявить все научные выводы SORA ложными, или основания тратить GPU
на эту ветку без checkpoints. Сохраняем точные ограниченные findings.
Далее — downstream response D против калиброванного контроля той же силы,
из основных направлений проекта. К алгоритмам не переходим по самому факту
отсутствия положительного результата в SORA audit.
