# Проверка SORA: согласованы ли forward, merge и ограничение вращения?

14 октября 2026. Read-only аудит официального кода до численных outputs.
Без обучения, загрузки моделей, агентов и GPU. Не попытка воспроизвести
benchmark статьи и не новый алгоритм ортогональной адаптации.

Источник: [MaeChd/SORA, layer.py](https://github.com/MaeChd/SORA/blob/24f62bfe84741e5613ae2e9f387f2e1f9bb64ba8/peft/tuners/sora/layer.py),
commit `24f62bfe84741e5613ae2e9f387f2e1f9bb64ba8`.
[Статья, arXiv v2](https://arxiv.org/html/2511.00051v2), раздел Transformation
и Theorem 2. Основной вопрос: соответствует ли опубликованная реализация
собственному forward при преобразовании checkpoint для inference?

1. Из pinned файла через AST извлечь неизменённые методы `compute_s_p`,
   `forward`, `get_delta_weight`, `merge`, `unmerge`. Исполнять их в минимальном
   Torch harness с явно заданными полями; не устанавливать авторский PEFT fork.
   Это проверка арифметики методов, не совместимости всего стека автора.
2. CPU FP64, dropout=0, bias=False, rectangular base 3×4. Два заранее заданных
   случая: initialization (`B=0`, `C=D`, diagonal=1), nontrivial fixed factors.
   Сверить forward с независимой плотной формулой; затем forward с экспортом
   `W + get_delta_weight`; отдельно проверить merge и round-trip unmerge.
   Сравнивать dense export до вызова forward, который сам вызывает unmerge.
3. Независимый исправленный export: `M=diag(d)W+sBA`,
   `K=s_P(DCᵀ−CDᵀ)`, `W_eff=(I+K)M`. Это алгебра forward автора,
   а не обученный или новый метод. Отдельно сохранить исходный W для корректного
   восстановления; не выдавать замену одной строки за исправление unmerge.
4. Проверить ограничение масштаба на семействе `C=t e1`, `D=t e2`,
   t=.01,.1,1,10, initial_s_p=1. Сравнить коэффициент из кода со scale из статьи
   при epsilon=.01. Для 2×2 skew K проверить `PᵀP−I=KᵀK` и stretch
   `sqrt(1+k²)`. Это допустимые синтетические параметры, не trained checkpoints.
5. Успех приёмки: forward совпадает с независимой формулой и исправленным
   export до 1e−12 relative/absolute, сохранённый base восстанавливается точно.
   Несовпадение author export/roundtrip публикуется как результат, не прячется
   за общим PASS. Записать SHA исходника/скрипта, версии, wall и ресурсный расход.

До расширения: проверить call sites оценки автора и доступность готовых весов.
Без этого не заключать, что опубликованные accuracy испорчены merge либо что
реальные факторы далеко от ортогональности. Исправления экспоненты/Cayley давно
известны; наличие ошибки реализации не обеспечивает самостоятельную статью B.
