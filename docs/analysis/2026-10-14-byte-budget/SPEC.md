# Контроль сжатия по байтам: спецификация до выходов

14 октября 2026. Этот этап проверяет пропущенный простой baseline, а не
новый алгоритм. Прежние выводы относились к одинаковому FP32 хранению и
числу элементов. Они не устанавливают лучшую ошибку при данном числе байт.

Бюджет tensor payload: 23,592,960 байт (прежние 5,898,240 FP32 элементов).
База неизменна и не входит в бюджет; все 144 q/k/v/o модуля входят.

Три фиксированных условия, без подбора рангов по качеству:

1. Сохранённый KFAC full-Delta rank8, FP32: прежний сильный baseline.
2. Fixed-D, rank15, FP16 факторы; D сохраняется FP32.
3. Fixed-D, rank30, INT8 факторы; D и quantization scales сохраняются FP32.

Для двух новых условий сжимаем эффективную низкоранговую ветвь
`L=D*s*B, R=A` через thin QR + SVD малого core без активаций.
Сингулярные значения распределяются поровну между L/R. INT8 — обычное
симметричное round-to-nearest в [-127,127], отдельный scale для каждой
latent-компоненты: столбца L и строки R. Нулевой компонент кодируется нулями
со scale=1. Сохраняем реальные safetensors, перечитываем и только затем
декодируем для inference. D фиксирован, не исходный m; это аффинное
представление `D*W0+LR`, не стандартный PEFT checkpoint без специального loader.

В бюджет включаем все D и scales. Проверить фактические dtypes, tensor payload,
размер каждого файла и сопроводительного JSON. Новые archives вместе с JSON
должны укладываться даже в указанный payload cap; baseline cap относится к
его payload. Не называть декодирование в FP32 уменьшением runtime VRAM или
ускорением: здесь проверяется хранение и функциональная ошибка.

Восемь OLD calibration вопросов, те же 32 gold continuation токена; exploratory
screen, не независимая оценка и не GSM8K accuracy. Source4 старых cached native
reference должны совпасть побитно; factorized native-r32/D versus native PEFT
проверяется на четырёх входах. Maximum control RMS <1% минимального среднего
эффекта сжатия. Все outputs конечны, после каждой подстановки source восстановлен.

CPU FP32 SDPA, 16 потоков, один процесс, защитный предел 30 минут, GPU нет.
Перед запуском meaningful tiny codec tests на CPU. Никакого optimizer/STE,
новых моделей или обучения. Не воспроизводим LoRAQuant целиком.

Решение: если любой новый простой baseline снижает mean teacher KL минимум
на 20% против KFAC rank8, считать прежний fixed-FP32 frontier недостаточным
для практической byte-budget заявки. Это заранее заданный инженерный screen,
не тест значимости. Тогда отдельная фиксированная оценка на имеющемся
128-case development наборе может подтвердить сравнение; повторно новый
набор для заявленного нового алгоритма здесь не нужен, потому что алгоритма
нет. При отсутствии такого выигрыша не расширять ранги/bitwidth сетку.
Результат сам по себе не устанавливает уровень B.
