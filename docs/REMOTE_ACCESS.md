## Что уже проверено в прежней схеме

- Пользователь подключил VM к Tailscale и опубликовал VPN в настройках Cloud.
- На VM работает `lora-dora-ssh-relay.service`, private endpoint
  `100.105.205.79:2222` → `185.185.59.19:22`; получен баннер OpenSSH.
  Это подтверждает TCP от VM до GPU, но не SSH-аутентификацию.
- В новой облачной задаче VPN configured, TCP grants пусты, `proxy:8088`
  возвращает Connection refused. Поле настройки TCP grants пользователю не найдено.
- Пользователь отказался от обращения в поддержку. `TCP_SUPPORT_REQUEST.md`
  — исторический черновик, не инструкция для следующего шага.
- HTTPS API и Cloudflare не были развёрнуты. Порты 80/443 VM заняты Docker;
  контейнеры и VPN не менялись. Прежние черновики API исключены из Git.

Прежний relay можно оставить: он не нужен для обычного SSH с самой VM.
Если пользователь решит отключить именно его, команда на VM:
`sudo systemctl disable --now lora-dora-ssh-relay.service`.

## Ограничение текущего облака

HTTP/HTTPS через inherited proxy и raw TCP через CONNECT — разные возможности.
Разрешённый Интернет не открывает автоматически SSH. Не менять локальную
network-policy.json, маршруты или TLS-проверку. Устанавливать новую VPN внутри
облачного контейнера не требуется. Проверка по паролю root невозможна до
доступного транспорта; поэтому первоначальный вход/установка CLI выполняются
пользователем из его VM-терминала.
