# Очередь проверки тезиса

13 октября 2026. Пользователь разрешил отложенный запуск и заменил прежнее
предложение о2GPU-ч разумным бюджетом по составу проверки. Новое обучение,
полные GSM8K quality прогоны и полный Mistral блок не включены.

## Исполнение

Один контроллер существующего admission, одна GPU-задача, затем CPU-задача.
Допуск: utilization строго ниже20%, занято строго меньше7168MiB, две успешные
проверки подряд с интервалом10секунд. Исключение неисправного устройства
задано по индексу и UUID в приватной конфигурации. Непосредственно перед
загрузкой дополнительно требуется8600MiB свободной VRAM и64GiB RAM.

После допуска задача не ждёт повторного освобождения карты внутри расчёта.
GPU-процесс завершается перед CPU-эталоном; cooperative lock освобождается,
CPU-процесс получает пустой CUDA_VISIBLE_DEVICES. Нет keeper, удержания VRAM
в ожидании CPU или чужого результата. Ошибка GPU-этапа блокирует CPU-этап.
Неудачная попытка и её артефакты сохраняются; автоматического бесконечного retry нет.

Защитные пределы: **5400 секунд GPU-этап, 14400 секунд CPU-этап**. Это лимиты
от зависания, не обещанные ETA и не целевой расход. Одна карта даёт максимум
1.5GPU-ч в этом блоке; CPU-эталон GPU-часов не добавляет. CPU workers используют
4threads. Времена, VRAM, RAM и прогресс записываются по ходу выполнения.

## GPU-этап

Одна загрузка native BF16 DoRA для original64, c=.995/.1.005 по всем V/O64,
removeD64. Проверки повторного original и gauged-removeD ограничены4примерами:
это технические контроли восстановления функции/dispatch, не полные no-op прогоны.
Затем custom dense и официальный pinned PEFT merge по64тем же входам.

Сравниваются max/RMS logit error, полный vocabulary KL, next-token margins,
argmax disagreements и gold NLL. Байт-хеши всех144dense attention projections
сопоставляют official/custom; прямое сравнение logits выполняется на4примерах
для дополнительной проверки. Нельзя делать вывод об их равенстве только по NLL.

CPU readback проверяет конечность каждого output. Immutable64MiB canary
проверяется периодически. Эти guards не сертифицируют отсутствие любой конечной
ошибки устройства, но останавливают обнаруженную порчу вместо сохранения
невалидных ответов.

## CPU-этап после освобождения GPU

Те же исходные BF16 checkpoint values продвигаются в FP32; это не восстановление
несохранённых FP32 pretrained weights. Autocast отключён. Повторяются те же
fixed-prefix условия и merge проверки; измеряется отличие эффекта removeD между
двумя исполнениями, с сохранением одних coefficients и входов.

**BF16 CUDA versus FP32 CPU одновременно меняет dtype и backend.** Это независимый
FP32 эталон для функциональной симметрии, но не чистый эксперимент, доказывающий
причину различий только числом бит. Если понадобится такая причинная атрибуция,
потребуется отдельный опыт на одном backend; автоматически он не добавляется.

CPU spectrum stage допускается, если средний FP32 logit RMS при gauge не больше
1% среднего RMS при removeD для обоих локальных c. Это заранее выбранный
практический screen, не универсальная гарантия функциональной эквивалентности.
При неразрешённой fidelity спектральное расширение пропускается с явной причиной.

При пройденном gate —18FP32 SVD (V/O, слои0/17/35, c=.995/1/1.005) на CPU,
entropy/effective rank/norm и независимый FP64 V/O block check с GQA replication.
Ранг идеального FP32 delta не приписывается BF16 deployment matrix.

## Проверки и продолжение

Перед постановкой прошли7CPU тестов, в том числе настоящая крошечная
Qwen3/DoRA: обе функции, точное восстановление state после исключения,
custom/official merge и байты проекций, alignment последних target logits,
NaN guard, границы допуска и освобождение GPU lock перед CPU.

Код: `execution/next-experiments/thesis_audit.py`,
`lora_dora_study/fidelity_audit.py`; admission переиспользован с приватной
JSON спецификацией. Source hashes проверяются перед обеими фазами.
Large logit caches, queue state и operational paths находятся вне Git;
точные пути — в ignored OPERATIONS_PRIVATE.md.

Следующий шаг: дождаться summary обеих фаз, проверить полноту64и все gates,
оценить изменение entropy при проверенном сохранении функций. Mistral имеет
смысл только после конкретного результата; отдельная полная очередь для него
сейчас не создана. Смена численного пути сама по себе не опровергает пользу DoRA
при обучении и не доказывает, что старые ablation эффекты были artifacts.
